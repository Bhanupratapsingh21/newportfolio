In the world of EdTech and premium content, "uploading a video" is just 5% of the journey [web:1]. To provide a buffer-free, secure experience, we must transform a single massive MP4 into hundreds of tiny, encrypted segments served via Adaptive Bitrate Streaming (ABR) [web:1].

Here is how we built a production-ready video pipeline using Node.js, FFmpeg, AWS S3, and Google Shaka Player [web:1].

## The Trigger: Event-Driven Orchestration

Once the S3 upload returns `200 OK`, the frontend calls our `confirm-upload` API [web:1].

**Why not S3 Triggers?** While S3 can trigger Lambda automatically, a manual confirmation API gives the application layer control to validate business logic (e.g., "Does this user have remaining storage quota?") before spinning up expensive compute resources [web:1].

### The Message Queue (SQS/BullMQ)

The API doesn't start transcoding [web:1]. It pushes a job into a **message queue** (Redis-backed BullMQ or AWS SQS) [web:1].

### Deep Engineering: The FFmpeg Command

We don't just "convert" the video [web:1]. We generate an **HLS (HTTP Live Streaming)** stack [web:1]. This creates a Master Playlist (`.m3u8`) and multiple stream variants (e.g., 1080p, 720p, 480p) [web:1].

<CodeBlock
    marginBottom="16"
    marginTop="8"
    codes={[
      {
        code:
`ffmpeg -i input.mp4 \\
  -map 0:v -map 0:a -s:v:0 1920x1080 -b:v:0 5000k \\
  -map 0:v -map 0:a -s:v:1 1280x720  -b:v:1 2800k \\
  -map 0:v -map 0:a -s:v:2 854x480   -b:v:2 1400k \\
  -f hls -hls_time 10 -hls_playlist_type vod \\
  -master_pl_name master.m3u8 \\
  -var_stream_map "v:0,a:0 v:1,a:1 v:2,a:2" \\
  output_%v.m3u8`,

## Content Protection: Multi-DRM (Widevine)

## Secure Playback: Signed Cookies vs. Signed URLs

You mentioned a "video signer URL." For HLS, there is a major technical hurdle: **A single signed URL for the `.m3u8` is not enough** [web:1]. The player will successfully download the playlist but will be blocked when it tries to fetch the individual `.ts` segments [web:1].

### The Solution: CloudFront Signed Cookies

Instead of signing every individual segment, our `get-video-signer-url` API sets **CloudFront Signed Cookies** [web:1].

<Column fillWidth gap="-1" marginBottom="16" marginTop="8">
<CodeBlock
    radius="none"

    codes={[
      {
        code:
`// CloudFront Signed Cookie Flow
// 1. Request: User clicks "Play"
// 2. API: Verifies user permissions
// 3. Response: Returns CloudFront URL and sets cookies

res.cookie('CloudFront-Policy', policy, { httpOnly: true, secure: true });
res.cookie('CloudFront-Signature', signature, { httpOnly: true, secure: true });
res.cookie('CloudFront-Key-Pair-Id', keyPairId, { httpOnly: true, secure: true });

// 4. Browser automatically sends these cookies with every .ts segment request`,
